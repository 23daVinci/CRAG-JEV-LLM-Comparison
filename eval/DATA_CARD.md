# eval/dataset.jsonl — data card

## Source

[HotpotQA](https://hotpotqa.github.io/) dev set, **distractor setting**
(`hotpot_dev_distractor_v1.json`), Yang et al. 2018, Stanford NLP.

## What's in this file

A frozen slice of 45 questions (32 bridge + 13 comparison), selected with a
fixed seed (20260915) from the full ~7.4k-question dev-distractor set. The full dev set is entirely
"hard" difficulty — HotpotQA's easy/medium questions exist only in the train split, not dev — so
difficulty is not a selection axis here.

Each line is one JSON record:

```json
{
  "id": "<HotpotQA _id>",
  "question": "...",
  "answer": "...",
  "type": "bridge" | "comparison",
  "level": "hard",
  "context": {"<Wikipedia title>": "<paragraph text>", ...},   // all 10 distractor-setting docs
  "gold_titles": ["<title>", ...]                                 // 2 titles, from supporting_facts
}
```

`gold_titles` is the ground truth this project uses for quality parity: selected-document-set
precision/recall/F1 against `gold_titles`, not a human or LLM-judged label. `answer` is kept for
reference but is not consumed anywhere in this pipeline — there is no generation step (see the
project's plan/README for why).

## Curation method

`scripts/curate_eval_set.py`, run once against a local copy of `hotpot_dev_distractor_v1.json`
(not committed — see `.gitignore`; the official host is
`http://curtis.ml.cmu.edu/datasets/hotpot/hotpot_dev_distractor_v1.json`, mirrored on Hugging Face
at `RAGLAB/data`). Selection: shuffle bridge and comparison questions separately under a fixed seed,
take the first 32 and 13 respectively, interleave. No filtering by content,
length, or difficulty beyond type — the goal is a representative, not a cherry-picked, slice.

## eval/injection_probes.jsonl

A separate synthetic test set for the injection-screening guard (plan milestone 6; raised from 12 to
40 pairs for threshold tuning — 12 split three ways by `eval/splits.json` left single-digit probes
per split). Prompt injection isn't organic to HotpotQA, so this ground truth is constructed, not
judged: 40 distractor passages (never gold documents) are sampled from `dataset.jsonl` under the
same fixed seed, and each produces a matched pair — one unmodified ("clean") copy and one with a
known injection string appended ("injected") — so the two differ only in the presence of the
injection text, not in topic or length. Generated by `scripts/generate_injection_probes.py`. Each
line:

```json
{
  "id": "probe-NNN-clean" | "probe-NNN-injected",
  "query_id": "<source dataset.jsonl record id>",
  "query": "...",
  "title": "<source passage title>",
  "text": "...",
  "is_injection": true | false
}
```

Scored via `jev-bench injection-eval` / `bench/injection_eval.py`'s `evaluate_injection_guard`.

## eval/splits.json

A deterministic train/val/test assignment of `dataset.jsonl`'s 45 query IDs (60/20/20, stratified by
`type`: 27/9/9 overall, 19/7/6 bridge, 8/2/3 comparison), generated by
`scripts/split_eval_queries.py`. Used to tune Jev's decision thresholds without ever touching test:
train picks a candidate threshold via a precision-recall sweep, val confirms it holds up
out-of-sample, test is scored exactly once at the locked threshold. `injection_probes.jsonl`
records inherit their split from their `query_id` here, not an independent assignment, so both
halves of a clean/injected pair always land together.

**Caveat, stated plainly**: 9 test queries is small enough that one flipped query moves test F1 by
about 11 points. Any number reported on the test split must carry a bootstrap CI over queries, never
a bare point estimate — see `docs/METHODOLOGY.md`.
