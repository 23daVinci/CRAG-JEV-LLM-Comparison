Much faster and cheaper; a likely accuracy cost, not yet statistically established.

One LangGraph workflow, two decision backends. The classification-style calls (is this passage relevant, is the evidence sufficient, should it retry) are answered either by an LLM (Groq) or by Jev, TypeSafe AI's model that returns typed probabilities instead of generated text.

Pilot held-out split

10 of 100 frozen HotpotQA questions, never seen during tuning. Jev's thresholds (relevance 0.40, injection 0.50) were tuned on an 80-query train split and confirmed on a 10-query val split. A first test attempt finished only 8 of 10 queries (network errors) and was discarded; this is the complete second run.

Objective labels

Output under test is the selected document set, scored against HotpotQA's own gold supporting facts. No LLM judge, no generation step.

Paired, live runs

Real Groq and Jev API calls, A/B interleaved per query against a frozen document pool hashed before and after each pair. The shared retrieve step ranks documents semantically with a local embedding model.

Small n, stated plainly

Read the speed and cost gaps as large and clear (latency p = 0.0020). Read the quality gap as likely but not established: its paired CI includes zero at n = 10, so a bigger split must confirm or rule it out.
